Stakeholder and System Requirements Specification
==================================================

This document says what the robot arm must do and why. It is the starting point of every trace
link in the project: the documents of the other repos link to the needs defined here.

.. note::

   This is a skeleton. The content comes in Phase 6.

What will go here
-----------------

The document follows the SYSMOD steps:

* the project and its problem statement (a stakeholder need with the category ``problem``);
* the stakeholders and their needs;
* the system objectives;
* the use cases, generated from the system model;
* the system requirements, written as EARS sentences with value fields (quantity, unit, limits).

Stakeholders, needs and requirements are written here as sphinx-needs. A tool turns them into
read-only stubs in ``model/generated/NeedStubs.sysml``, so that the SysML model can refer to them.
